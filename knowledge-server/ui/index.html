How documents work

A document is one durable piece of knowledge. Its collection and family id form a stable identity; every save creates a new immutable version.

Collection
kernel is injected into every fresh agent session. docs is materialized for trigger-based loading.
Family id
A stable, path-safe name shared by every version of the same document, such as incident-recovery.
Version and status
Each save creates a numbered version. Drafts stay out of releases; the active version is eligible for the next release; replaced versions become superseded history.
Content and metadata
The title and Markdown body carry the knowledge. Tier, owner, audience, and triggers describe how operators and agents should use it.
Links
Version-specific reference and supersedes relationships connect exact document versions and are checked before release.
